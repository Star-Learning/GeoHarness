# GeoHarness 宣传视频方案

> **文档状态**：对外发布素材，不属于运行时技术契约。

## 推荐做法

先做一条 **75 秒横版主视频**，重点展示一个复杂任务和一次对话式参数修改，不要在一条视频里完整讲完 7 个案例。

- 横版：`1920 × 1080`，用于公众号、GitHub、B 站
- 竖版：`1080 × 1920`，用于小红书；从同一素材中分别裁切输入框、Agent 区和地图区
- 主案例：Scenario 06 多条件选址
- 第二亮点：Scenario 05 从 500 米修改为 200 米

## 75 秒镜头脚本

| 时间 | 画面 | 字幕 / 口播 |
| --- | --- | --- |
| 0–4 秒 | 主界面快速出现，地图和 Agent 区同时入镜 | “一句话，让 Agent 自己完成 GIS 分析。” |
| 4–12 秒 | 放大输入框，输入多条件选址 Prompt | “不用选择预设案例，直接描述空间目标。” |
| 12–25 秒 | 右侧计划逐步出现并打勾 | “Agent 自动发现数据、拆解任务并调用 GIS 工具。” |
| 25–42 秒 | 中间地图逐层出现道路、缓冲区、河流和候选建筑 | “每一步都有对应图层，过程可见，结果可核查。” |
| 42–52 秒 | 放大最终统计与候选建筑图层 | “两个距离条件共同筛选，最终得到 27 栋候选建筑。” |
| 52–65 秒 | 切到参数修改案例，输入“改成 200 米” | “条件变了，不必从头再来：复用有效步骤，只重算受影响部分。” |
| 65–75 秒 | 7 个案例快速蒙太奇，最后停在 GitHub 地址 | “GeoHarness 已开源。让 GIS Agent 真正开始工作。” |

## 拍摄与剪辑要点

1. 使用真实 Agent 会话和真实数据录制，提前准备好 Provider，避免录到连接错误。
2. 开始前创建干净会话，统一浏览器尺寸；录制素材建议高于 1080p，最后导出 `1920 × 1080`。
3. 执行等待部分加速到 `1.5–2 倍`，但保留步骤打勾、图层出现和结果返回的关键时刻。
4. 关键区域使用 `115%–135%` 的平滑放大：先看输入，再看 Agent 步骤，然后看地图与结果。
5. 字幕保持短句，每屏不超过两行；不要用大段技术术语遮挡地图。
6. 竖版不要简单裁掉两侧。输入、步骤、地图和结果应分镜展示，最后再用一次完整界面收尾。

## 建议使用的完整 Prompt

```text
找出距离主要道路 Broadway 300 米以内，同时距离 Hudson River 和 East River 至少 800 米的建筑。请自动选择可用数据，展示每一步生成的图层，报告最终建筑数量，并说明筛选过程。
```

参数修改镜头追加一句：

```text
把道路缓冲距离改成 200 米，其他条件保持不变，并更新图层和统计结果。
```
