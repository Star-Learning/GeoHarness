# GeoHarness Agent 测试 Prompt

本文收录一组可直接粘贴到 GeoHarness 底部对话框的端到端测试输入。它们面向当前仓库中
冻结的 NYC 官方数据快照，用来验证 Agent 是否会根据自然语言目标自主发现数据、规划步骤、
选择 GIS 工具并展示真实结果，而不是匹配某个预设流程。

## 使用前提

- 在左下角“模型与 API Key”中配置一个可用的 Harness 模型 Provider。
- 每个“测试输入”代码块应原样单独发送；除“连续修订”外，建议使用新的空工作区。
- 页面上的步骤、图层和最终回答都应来自本次真实工具调用。测试人员应核对数据来源、单位、
  CRS、要素数量和错误信息，不把下方的“观察重点”复制进对话框。
- 当前数据目录覆盖 Manhattan/NYC。超出目录能力的请求应明确说明缺少数据，不应编造结论。

## 1. 自主发现数据目录

测试输入：

```text
请先查看你现在真正能够访问的 GIS 数据。告诉我有哪些官方数据集和图层、每个图层覆盖什么区域、包含多少个要素，以及它们适合做哪些分析。请说明数据发布方和快照日期；不要根据示例名称猜测，也先不要做空间分析。
```

观察重点：Agent 应先发现当前官方数据目录，再列出 buildings、roads、rivers、districts 和
lower_manhattan_buildings；回答中的数量应来自工具结果，而不是写死的介绍文字。

## 2. 建筑数据质量检查

测试输入：

```text
请自主找到适合检查 Manhattan 建筑的数据，对它做一次完整的数据质量检查。至少报告坐标系、几何类型、范围、字段、缺失值、无效几何和面积分布，并把被检查的建筑图层显示在地图上。最后用简洁中文判断这份数据是否适合继续做米制空间分析，并说明判断依据。
```

观察重点：应看到数据发现、载入/检查和必要的米制几何计算；最终判断应引用本轮真实统计。

## 3. 河流 500 米范围内建筑

测试输入：

```text
请使用当前可用的真实官方数据，找出 Manhattan 中距离 Hudson River 或 East River 500 米范围内的建筑。请自行选择正确数据和 GIS 步骤，距离计算必须使用适合纽约的米制投影。把河流、500 米范围和筛选出的建筑都显示在地图上，并在最终回答中报告输入建筑数、命中建筑数、使用的距离和坐标系。
```

观察重点：计划应由 Agent 生成，缓冲距离必须是 500 米；地图和最终数字应来自实际工具输出。

## 4. Broadway 200 米范围内建筑

测试输入：

```text
请从可用的 NYC 官方道路数据中识别 Broadway，找出距离 Broadway 200 米以内的建筑。请自行规划并执行分析，不要套用固定示例。地图上同时保留 Broadway、200 米缓冲范围和候选建筑，最终说明一共检查了多少栋建筑、选中了多少栋，并写明实际使用的距离单位和投影。
```

观察重点：Agent 应从道路属性识别 Broadway，不能把 200 米替换成默认距离；图层应随步骤逐步出现。

## 5. 非预设距离 275 米

测试输入：

```text
请分析 Broadway 周边 275 米内有哪些建筑。使用真实官方数据，自主决定所需工具和执行顺序，按米制距离精确计算。请展示道路、275 米范围和结果建筑，并给出命中数以及最远命中建筑到 Broadway 的距离摘要。
```

观察重点：这是参数泛化测试。执行计划和结果必须始终显示 275 米，不应先运行其他距离再替换。

## 6. 按 Community District 统计建筑

测试输入：

```text
请使用当前可访问的官方 Community District 边界和建筑数据，统计每个 Manhattan Community District 内的建筑数量与建筑占地面积总和。请自行处理坐标系和空间关联，在地图上展示带统计字段的行政区图层，并在回答中给出按建筑数量从高到低的表格，同时说明无法归入任何行政区的建筑数。
```

观察重点：应执行真实的分区聚合，最终表格应引用聚合工具返回的数据，地图应展示派生行政区图层。

## 7. 道路与河流多约束筛选

测试输入：

```text
请找出既位于 Broadway 300 米以内、又位于 Hudson River 或 East River 500 米以内的 Manhattan 建筑。请从数据目录自主选择道路、河流和建筑数据，明确处理两个空间条件的先后关系。地图上保留两个范围和最终交集，回答中分别报告每个条件筛出的数量以及同时满足两个条件的数量。
```

观察重点：应有两条独立空间约束和最终交集，不应只执行其中一条；中间图层与数字需可追溯。

## 8. 建筑面积与分布分析

测试输入：

```text
请对当前官方 Manhattan 建筑数据计算真实的占地面积，并分析面积分布。报告有效样本数、最小值、中位数、平均值、最大值和明显异常的大型建筑；面积单位使用平方米。请把带面积字段的派生图层显示在地图上，并说明你为避免经纬度直接算面积采取了什么处理。
```

观察重点：应先使用合适的米制投影计算几何，再分析派生面积字段；不得直接把经纬度平方当平方米。

## 9. 最近道路与距离

测试输入：

```text
请为每一栋可用的 Lower Manhattan 官方建筑找到最近的道路，并计算到该道路的距离（米）。在地图上展示建筑和道路，回答中给出建筑总数、最近距离的中位数和最大值，并列出距离道路最远的 10 栋建筑及其最近道路名称。请说明同距离并列时如何处理。
```

观察重点：应调用最近要素分析而非缓冲近似；每个输入建筑只应对应一个最近距离结果。

## 10. 导出分析结果

测试输入：

```text
请找出 Broadway 200 米范围内的建筑，完成检查后把结果同时导出为 GeoJSON 和 CSV。请在地图上显示结果，并在最终回答中给出两个真实导出文件的名称或工作区路径、要素数量、坐标系，以及 CSV 中几何字段的处理方式。任何导出失败都要明确报告，不能只说“已导出”。
```

观察重点：除了空间分析，还应出现两次真实导出；返回路径必须来自工具结果并限定在当前工作区。

## 11. 同一会话连续修订

先发送：

```text
请使用真实官方数据找出 Broadway 275 米内的建筑，展示分析步骤、相关图层和最终数量。
```

第一次完成后，在同一会话继续发送：

```text
把刚才的距离改成 200 米。请复用仍然有效的数据和中间结果，只重算受距离变化影响的步骤，并清楚说明哪些步骤复用了、哪些步骤重新执行了；地图和最终回答都更新为 200 米结果。
```

观察重点：第二轮必须理解“刚才”的上下文，参数从 275 米更新为 200 米，不能保留旧结果冒充新结果。

## 12. 数据能力边界

测试输入：

```text
请统计上海市浦东新区所有医院在 2025 年服务的人口，并在地图上生成每家医院 15 分钟驾车可达范围。只允许使用你当前能够真实访问的数据；如果缺少医院、人口或路网时效数据，请逐项说明缺口和完成分析所需的外部数据，不要用 Manhattan 数据替代，也不要编造数量或地图结果。
```

观察重点：当前 NYC 目录无法支持该目标。Agent 应停在数据能力说明，不应创建虚假图层、数量或可达范围。

## 统一验收清单

每次测试至少核对以下项目：

1. Agent 是否先理解目标并根据目标自主选择数据和工具；
2. 右侧步骤是否按照真实执行状态从等待、运行逐步变为成功或失败；
3. 左侧输入和派生图层是否随真实工具结果出现，透明度滑块是否保持地图可见；
4. 地图是否支持滚轮缩放、拖拽、适配范围和要素检查；
5. 最终回答是否包含真实结果、单位、CRS、来源和必要限制；
6. 失败时是否明确暴露 Provider、数据或工具错误，且没有回退到固定流程伪造成功。
